The Meetings API lets you programmatically manage every meeting in your ConnectMeetings organization. Use these endpoints to create and schedule meetings, update meeting details, retrieve meeting records for reporting, and remove meetings that are no longer needed. All requests require a valid Bearer token and are scoped to your organization.

---

## GET /meetings

Retrieve a paginated list of all meetings in your organization. Use the `status` query parameter to filter by lifecycle stage.

<ParamField query="status" type="string">
  Filter meetings by status. Accepted values: `draft`, `published`, `completed`.
</ParamField>

<ParamField query="page" type="integer" default="1">
  The page number to return.
</ParamField>

<ParamField query="per_page" type="integer" default="20">
  The number of meetings to return per page. Maximum: `100`.
</ParamField>

```bash
curl -X GET "https://api.connectmeetings.ca/v1/meetings?status=published&page=1&per_page=10" \
  -H "Authorization: Bearer cm_live_xxxx"
```

## POST /meetings

Create a new meeting in your organization. The meeting is created in `draft` status by default. Publish it from the ConnectMeetings dashboard or by updating the `status` field via `PATCH /meetings/{id}`.

<ParamField body="title" type="string" required>
  The display title of the meeting.
</ParamField>

<ParamField body="starts_at" type="string" required>
  The scheduled start time in ISO 8601 format. Include a timezone offset (e.g., `-05:00`) to avoid ambiguity.
</ParamField>

<ParamField body="ends_at" type="string" required>
  The scheduled end time in ISO 8601 format. Must be after `starts_at`.
</ParamField>

<ParamField body="location" type="string">
  The physical address or virtual meeting link where the meeting takes place.
</ParamField>

<ParamField body="type" type="string">
  The meeting type. Accepted values: `regular`, `special`, `committee`, `public_hearing`. Defaults to `regular`.
</ParamField>

<ParamField body="description" type="string">
  An optional plain-text description or public notice for the meeting.
</ParamField>

```bash
curl -X POST https://api.connectmeetings.ca/v1/meetings \
  -H "Authorization: Bearer cm_live_xxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "City Council Regular Meeting",
    "starts_at": "2024-04-15T14:00:00-05:00",
    "ends_at": "2024-04-15T16:00:00-05:00",
    "location": "City Hall, Council Chambers",
    "type": "regular"
  }'
```

```json
{
  "data": {
    "id": "mtg_01hq8zvpxk3rn5bk9d7w2e4f",
    "title": "City Council Regular Meeting",
    "status": "draft",
    "type": "regular",
    "starts_at": "2024-04-15T14:00:00-05:00",
    "ends_at": "2024-04-15T16:00:00-05:00",
    "location": "City Hall, Council Chambers",
    "description": null,
    "created_at": "2024-03-28T09:15:00Z",
    "updated_at": "2024-03-28T09:15:00Z"
  }
}
```

<ResponseField name="data" type="object">
  The newly created meeting object.

  <Expandable title="Meeting object fields">
    <ResponseField name="data.id" type="string">
      The unique identifier assigned to the new meeting.
    </ResponseField>
    <ResponseField name="data.title" type="string">
      The display title of the meeting.
    </ResponseField>
    <ResponseField name="data.status" type="string">
      Always `draft` for newly created meetings.
    </ResponseField>
    <ResponseField name="data.type" type="string">
      The meeting type: `regular`, `special`, `committee`, or `public_hearing`.
    </ResponseField>
    <ResponseField name="data.starts_at" type="string">
      The scheduled start time in ISO 8601 format.
    </ResponseField>
    <ResponseField name="data.ends_at" type="string">
      The scheduled end time in ISO 8601 format.
    </ResponseField>
    <ResponseField name="data.location" type="string">
      The location of the meeting, if provided.
    </ResponseField>
    <ResponseField name="data.description" type="string">
      The meeting description, or `null` if not set.
    </ResponseField>
    <ResponseField name="data.created_at" type="string">
      The UTC timestamp when the meeting was created.
    </ResponseField>
    <ResponseField name="data.updated_at" type="string">
      The UTC timestamp of the most recent update.
    </ResponseField>
  </Expandable>
</ResponseField>

## GET /meetings/\{id\}

Retrieve a single meeting by its unique ID. Use this endpoint to fetch full meeting details, including type and description fields not returned in list responses.

<ParamField path="id" type="string" required>
  The unique identifier of the meeting to retrieve.
</ParamField>

```bash
curl -X GET https://api.connectmeetings.ca/v1/meetings/mtg_01hq8zvpxk3rn5bk9d7w2e4f \
  -H "Authorization: Bearer cm_live_xxxx"
```

```json
{
  "data": {
    "id": "mtg_01hq8zvpxk3rn5bk9d7w2e4f",
    "title": "City Council Regular Meeting",
    "status": "published",
    "type": "regular",
    "starts_at": "2024-04-15T14:00:00-05:00",
    "ends_at": "2024-04-15T16:00:00-05:00",
    "location": "City Hall, Council Chambers",
    "description": "Monthly regular session of City Council.",
    "created_at": "2024-03-28T09:15:00Z",
    "updated_at": "2024-04-01T14:30:00Z"
  }
}
```

<ResponseField name="data" type="object">
  The full meeting object. See [POST /meetings](#post-meetings) for a description of all fields.
</ResponseField>

## PATCH /meetings/\{id\}

Update one or more fields on an existing meeting. You only need to include the fields you want to change — all other fields remain unchanged.

<ParamField path="id" type="string" required>
  The unique identifier of the meeting to update.
</ParamField>

<ParamField body="title" type="string">
  A new display title for the meeting.
</ParamField>

<ParamField body="starts_at" type="string">
  A new scheduled start time in ISO 8601 format.
</ParamField>

<ParamField body="ends_at" type="string">
  A new scheduled end time in ISO 8601 format.
</ParamField>

<ParamField body="location" type="string">
  An updated location for the meeting.
</ParamField>

<ParamField body="type" type="string">
  An updated meeting type: `regular`, `special`, `committee`, or `public_hearing`.
</ParamField>

<ParamField body="description" type="string">
  An updated plain-text description.
</ParamField>

<ParamField body="status" type="string">
  Update the meeting's lifecycle status. Accepted values: `draft`, `published`, `completed`.
</ParamField>

<Warning>
  Changing the `status` of a `published` meeting to `draft` will hide it from public-facing views and any integrations that query published meetings.
</Warning>

```bash
curl -X PATCH https://api.connectmeetings.ca/v1/meetings/mtg_01hq8zvpxk3rn5bk9d7w2e4f \
  -H "Authorization: Bearer cm_live_xxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "location": "City Hall, Council Chambers (Room 1A)",
    "status": "published"
  }'
```

```json
{
  "data": {
    "id": "mtg_01hq8zvpxk3rn5bk9d7w2e4f",
    "title": "City Council Regular Meeting",
    "status": "published",
    "type": "regular",
    "starts_at": "2024-04-15T14:00:00-05:00",
    "ends_at": "2024-04-15T16:00:00-05:00",
    "location": "City Hall, Council Chambers (Room 1A)",
    "description": "Monthly regular session of City Council.",
    "created_at": "2024-03-28T09:15:00Z",
    "updated_at": "2024-04-02T10:05:00Z"
  }
}
```

<ResponseField name="data" type="object">
  The full updated meeting object reflecting all changes. See [POST /meetings](#post-meetings) for a description of all fields.
</ResponseField>

## DELETE /meetings/\{id\}

Permanently delete a meeting and all associated data, including its agenda and action items. This action cannot be undone.

<ParamField path="id" type="string" required>
  The unique identifier of the meeting to delete.
</ParamField>

<Warning>
  Deleting a meeting also permanently deletes its agenda items and action items. Export any data you need to retain before calling this endpoint.
</Warning>

```bash
curl -X DELETE https://api.connectmeetings.ca/v1/meetings/mtg_01hq8zvpxk3rn5bk9d7w2e4f \
  -H "Authorization: Bearer cm_live_xxxx"
```

A successful delete returns HTTP `204 No Content` with an empty response body.

<Tip>
  To archive a completed meeting while retaining its data, update its `status` to `completed` via `PATCH /meetings/{id}` instead of deleting it.
</Tip>
