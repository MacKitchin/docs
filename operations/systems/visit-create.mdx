Visit Create is the event-registration and visitor-data platform Connect uses for hosted buyers, suppliers, eTourism destination marketers, and Sports/BizBash pass holders. The admin UI is [create.visitcloud.com](https://create.visitcloud.com/login). The product API is **Create v2**. This site documents **our usage**, not the vendor's marketing site.

<Info>
- **Captured:** 12 August 2026
- **API:** [Create v2 OpenAPI](https://api.visitcloud.com/create/docs/specs/create-v2.json)
- **Base:** `https://api.visitcloud.com/create/v2`
- **Salesforce named credential:** `Visit_API`
- **Code:** `sf-visit-webhook`
- **Agent tooling:** `visit-create` MCP and the `visit-create-api` plugin skill
</Info>

<Warning>
  Do not put API keys, webhook signing tokens, or visitor records on this site.
</Warning>

## What it is for us

An **expo** in Visit is one event instance. A **visitor** is a person registered against that expo. A **partner** is an exhibiting company. A **registration type** is the badge / form category. Almost every API call is scoped by `expoId`.

Connect uses Visit as the system of capture. Salesforce `connect-prod` is the system of record after the webhook lands. The human path after that is [Hosted buyer operations](/hosted-buyer-support/registration-and-operations). The five Apex pipelines are on [Visit Create workflows](/operations/systems/visit-create-workflows). The HTTP surface is on [Visit Create API](/operations/systems/visit-create-api).

| Visit concept | Salesforce |
| --- | --- |
| Expo | `Marketplace__c`, matched on `Visit_Expo_Id__c` |
| Visitor (hosted buyer, eTourism, brand/industry pass) | `Registration__c` + Contact (+ Account) |
| Visitor (Connect supplier) | `Supplier_Registration__c` + Contact + Account |
| Visitor / order / webhook receipt | `Visit_Webhook_Log__c`, `Visit_Webhook_Activity__c` |
| Registration type | Hard-coded filter per pipeline (see below) |

## Salesforce `Marketplace__c` lookup

Processors abort with "No Marketplace\_\_c found for Visit Expo ID" when `Marketplace__c.Visit_Expo_Id__c` does not match the incoming `expoId`.

A SOQL query from this session's Salesforce MCP user returned **null** on `Visit_Expo_Id__c` for every Marketplace row. That is likely field-level security on the connected user, not proof the field is empty — the webhook repo documents concrete Marketplace IDs paired to expo IDs, and Marketplace 2026 webhooks were firing the same day. Do not "fix" the field from this site.

Event **dates** still come from the [Events portfolio](/events/overview). Visit start/end can disagree with the public site (Texas 27–28 vs 28–29 October; South + Faith 9–11 vs 9–10 November). Report both. Do not reconcile.

## What not to do

- Do not list visitors, partners, emails, or orders on this site.
- Do not create, update, or delete Visit records from an agent session unless a human asked for that specific write.
- Do not copy webhook URLs that contain `sig=`, Power Automate secrets, or Zapier catch tokens.
- Do not leak Visit internals onto the Exhibitor or Hosted Buyer guide tabs.
