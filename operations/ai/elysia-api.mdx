## Environments

| Environment | API base | Token / IdP |
| --- | --- | --- |
| Stage (console default) | `https://api.stage.ai.informa.com` | `https://idp.dev.ai.informa.com/oauth2/token` |
| Dev (complete API notes) | `https://api.dev.ai.informa.com` | same IdP domain; AWS `eu-west-1` |
| Prod | **Unconfirmed** in the console handoff | Unconfirmed |

Set `ELYSIA_API_BASE` and `ELYSIA_TOKEN_URL` rather than hard-coding.

## Authentication

```text
POST https://idp.dev.ai.informa.com/oauth2/token
Content-Type: application/x-www-form-urlencoded
grant_type=client_credentials
scope=elysia/api
```

Use HTTP Basic (`client_id:client_secret`) or the form body. Response is a Bearer JWT (`expires_in` 3600 in the notes). Send `Authorization: Bearer <token>`.

Cloudflare Access (`ELYSIA_CF_USER` / `ELYSIA_CF_PASS`) is a **second** layer for docs and the console, not a substitute for the JWT.

Required on chat: **app ID** (`appId` / `ELYSIA_APP_ID`).

## Chat (what we actually call)

Console and Web App use:

```text
POST /v1/ai/chat/stream/completion
```

SSE stream. Required body fields in the skill: `appId`, `query`. Common optional fields: `name_of_model`, `model` (`azure` / `aws`), `chat_session`, `collection_name`, `output_type` (`markdown` / `html`), `response_language`, `tokens`, `metadata`.

<Warning>
  The console handoff: **do not switch to `/v2/ai/chat/completion`**. That path was previously unavailable on stage. The complete API markdown also lists `/v2` and `/v3` stream completion paths. If you need those, confirm against live OpenAPI. Do not pick a winner here.
</Warning>

Related chat ops in the skill: `PATCH /v1/ai/chat/archive`, `PATCH /v1/ai/chat/pin`, `DELETE /v1/ai/chat/conversation/session/{session_id}`.

The Elysia chat API is a **plain completion** endpoint. Native tool calling is not assumed. The Web App and console bridge drive an agent loop: the model emits a tool call, local MCP runs it, the result is sent back.

## Agents, content, apps

From the skill and endpoint reference (v1 and often v2):

| Area | Examples |
| --- | --- |
| Agents | `GET/POST /v1/ai/agents`, get/update/delete by id, status (`published` / `unpublished`), permissions, search, favourite, rating, brand-agent |
| Content / ingestion | `POST /v1/ai-ingestion/process-documents`, `GET /v1/ai-ingestion/health`, `GET /v1/ai/content`, delete files on an app collection |
| Assets | `POST/GET/DELETE /v1/ai/assets/{asset_type}` (`image`, `document`, `audio`, `video`) |
| Apps | `GET /v1/ai/apps/list`, `GET /v1/ai/apps/info?id=` |
| Dashboard | `GET /v1/ai/dashboard/powerbi` |
| Health | `GET /v1/ai/health`, `GET /v1/ai/openapi.json` |

## Local clients

```bash
cd /Users/william.kitchin/repos/elysia-console
python3 elysia_console.py          # http://localhost:8765/  tester + chat
python3 elysia_mcp_bridge.py "…"   # CLI tool loop
```

Postman: `elysia-apis-external.postman_collection.json` plus `elysia-external-dev.postman_environment.json` in the console repo and `~/Elysia API Docs`. Do not commit filled environments.

MCP profiles the console can advertise (read-only by default): **Salesforce**, **Visit Create**, **Power BI**. Mutating tools need `MCP_ALLOWED_TOOLS` or `MCP_ALLOW_ALL_TOOLS=1`.
