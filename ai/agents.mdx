## What grounds them

An agent is only as good as what it is allowed to read. Retrieval scope by agent type:

| Agent type | May ground on | Must not ground on |
| --- | --- | --- |
| Customer-facing | Customer FAQs library (~31 grounded Q&A pairs with confidence scores), Knowledge Articles, the Live Events wiki | Raw email, project pages, marketing site copy, anything marked Deprecated |
| Employee-facing | Company OS canonical sources, the Salesforce Knowledge Base, Supplier Knowledge Intelligence | Anything marked Deprecated without saying so |
| Data and ops | `connect-prod` directly, plus the [data model](/systems/data-model) and [metrics](/systems/metrics) definitions | Cached or derived figures presented as live |

<Warning>
  **The stale-facts problem is the central risk.** Multiple event sites publish contradictory dates, hosts, venues, and cancellation policies - see [Known issues](/governance/known-issues). Restricting customer-facing chatbots to the Live Events wiki is the mitigation, and it only works if the wiki stays current. The refresh SOP is not optional.
</Warning>

## Automation already in place

The AI roster sits on top of substantial existing automation, not on a blank slate.

|  |  |
| --- | --- |
| Automation records | 235 |
| Active flows | 92 |
| Documented | Salesforce automation is catalogued; **Notion and Zapier automations are not yet documented** |

<Tip>
  Record every new workflow in the AI & Agent Library **before** launch, not after. Undocumented automation is how the 235-record catalogue became hard to reason about in the first place.
</Tip>

## Recording a new agent or asset

The AI & Agent Library takes one row per asset with these properties:

| Property | Values |
| --- | --- |
| Asset Type | Agent, Prompt, MCP Tool |
| Platform | Salesforce, Notion, Cursor, HubSpot, Other |
| Status | Active, and other lifecycle states |
| Owner | A person from Master People |
| Docs Link | The canonical documentation page |
